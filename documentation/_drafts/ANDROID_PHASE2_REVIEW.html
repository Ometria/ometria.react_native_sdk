Android Docs — Phase 2 Fixes for Review

5 fixes applied to documentation/docs-android/, each cross-referenced against the live SDK source at ometria.android_sdk @ master.

The new Docusaurus Android docs were ported verbatim from the legacy README_android.md, then reviewed for defects. The issues below were found in the source README and have been fixed in the docs. Each item shows the change, the file, the reason, and (where applicable) the SDK source line confirming it. Build verified clean (pnpm build, zero broken-link warnings).

Group 1 — Documentation/data inconsistencies

1OmetriaBasketItem description copy-pasted from OmetriaBasket

File: docs-android/events/basket-events.md § OmetriaBasketItem
-An object that describes the contents of a shopping basket.
+An object representing one entry of a particular item in a basket.

Why: The first sentence was verbatim the description of OmetriaBasket (one section above). OmetriaBasketItem represents a single line item, not the whole basket.

SDK source: the new wording is taken directly from OmetriaBasketItem.kt's class docstring: "An object representing one entry of a particular item in a basket."

2OmetriaBasket.totalPrice type cased (float, ...) instead of (Float, ...)

File: docs-android/events/basket-events.md § OmetriaBasket → Properties
-* `totalPrice`: (`float`, required) - A float value representing the pricing.
+* `totalPrice`: (`Float`, required) - A float value representing the pricing.

Why: Kotlin's primitive is Float (capital F). The basket properties table used lowercase; the item table immediately below it used the correct capitalised Float. Now consistent.

SDK source: OmetriaBasket.kt declares val totalPrice: Float. The full data class init is OmetriaBasket(id: String? = null, totalPrice: Float, currency: String, items: List<OmetriaBasketItem> = listOf(), link: String? = null) — the docs table now matches.

3loggingEnabled(true) example dropped optional parameters

File: docs-android/troubleshooting.md
Before Ometria.initialize( application = this, apiToken = "YOUR_API_TOKEN", notificationIcon = R.drawable.ic_notification_nys ).loggingEnabled(true)
After Ometria.initialize( application = this, apiToken = "YOUR_API_TOKEN", notificationIcon = R.drawable.ic_notification_nys, notificationColor = ContextCompat.getColor(this, R.color.colorAccent), notificationChannelName = "Custom Channel Name" ).loggingEnabled(true)

Why: The Installation page's main init example uses the full 5-arg form. The Troubleshooting page's "advanced logging" example previously dropped notificationColor and notificationChannelName. Both forms compile (the optional params have defaults), but readers comparing the two were unsure why parameters appeared and disappeared. Now the only difference between the two examples is the .loggingEnabled(true) chain — which is the actual point of the snippet.

SDK source: Ometria.kt declares fun initialize(application: Application, apiToken: String, notificationIcon: Int, notificationColor: Int? = COLOR_DEFAULT, notificationChannelName: String = OMETRIA_CHANNEL_NAME). Both optional params have defaults; passing them explicitly with the documented values is harmless and makes the example consistent with the Installation page.

Group 2 — Misleading or outdated content

4intro.md event-tracking bullet rephrased

File: docs-android/intro.md
-1. Tracking customer behaviour through events - handled by Ometria. 2. Sending and displaying push notifications - requires the app developers.
+1. **Tracking customer behaviour** through events - a subset of events is automatically handled by the Ometria SDK, but you have to customize it to your needs. 2. **Sending and displaying push notifications** - requires the app developers.

Why: The original bullet implied event tracking was zero-effort. The Events page makes clear that most events are manually tracked. New wording matches the React Native and (now) iOS intros.

5Removed their_id jargon from customer-facing docs

File: docs-android/events/product-events.md § "View list of products"
-* "id" which should be an attribute their_id that exists in the Ometria database. For example "red".
+* "id" which should be the attribute identifier as it exists in the Ometria database. For example "red".

Why: their_id reads like an internal database column name. The same wording appears in iOS (already fixed) and React Native (still pending).
